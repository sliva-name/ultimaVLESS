# UltimaVLESS для Android

Мобильная версия UltimaVLESS: тот же интерфейс и та же логика, что на десктопе, поверх нативного VPN-сервиса Android с ядром Xray.

## Как это устроено

```
┌──────────────── WebView (Capacitor) ────────────────┐
│  src/renderer      интерфейс десктопа + mobile/src/ui │
│  src/main          main-процесс десктопа без изменений│
│                    (сессии, автопереключение, пинг,   │
│                    подписки, генератор конфигов Xray) │
│  mobile/src        платформенный слой: шимы Node и    │
│                    Electron, замены системных сервисов│
└───────────────────────┬──────────────────────────────┘
                        │ плагин UltimaCore (Kotlin)
┌───────────────────────┴──────────────────────────────┐
│  UltimaVpnService   VPN-туннель, уведомление, Always-on│
│  CoreRuntime        Xray (libv2ray v26.10.21)         │
│  NetProbes          сокеты для пинга и проверок        │
└──────────────────────────────────────────────────────┘
```

- **Main-процесс десктопа работает в WebView как есть.** Модули, которые на десктопе говорят с ОС (запуск `xray.exe`, системный прокси, маршруты TUN, UAC, логи в файлы), подменяются Android-реализациями из `mobile/src/platform` на этапе сборки: плагин в `vite.config.mts` меняет модуль по его пути. Всё остальное (`ConnectionManager`, монитор соединения, обновление подписок, пинг, IPC-обработчики) — тот же код, что в десктопе.
- **Node и Electron** заменены тонкими шимами (`mobile/src/node`, `mobile/src/electron`): сокеты проб идут в нативный плагин, `ipcMain.handle` вызывается напрямую из моста `backend/bridge.ts`, который заменяет preload-скрипт.
- **Xray** — тот же `BUNDLED_XRAY_VERSION`, что на десктопе; ядро работает внутри процесса приложения, конфиг генерирует десктопный `XrayConfigPipeline` (TUN-инбаунд получает дескриптор от `VpnService`).
- **Само приложение исключено из своего VPN**, поэтому исходящие соединения Xray, проверки и загрузка подписок идут напрямую, без `protect()` для каждого сокета. Как и на десктопе, пока подключено, сервер в списке не выбирается и пинг не запускается.

## Отличия от десктопа

| Десктоп                                     | Android                                                                                                           |
| ------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Режим TUN                                   | Режим **VPN** — системный `VpnService`, разрешение запрашивается при первом подключении                           |
| Режим «Прокси» (системный прокси)           | **Только прокси** — локальные SOCKS5 `127.0.0.1:10808` и HTTP `127.0.0.1:10809`, приложения настраиваются вручную |
| Приложения по имени `.exe`                  | Приложения по имени пакета (`org.telegram.messenger`); фильтрация делается самим `VpnService`                     |
| Иконка в трее                               | Уведомление со скоростью и кнопкой «Отключить», плитка в быстрых настройках, Always-on VPN                        |
| Открыть папку с логами                      | Поделиться логами                                                                                                 |
| Выбор сетевого адаптера, поиск мешающих VPN | Не нужны: Android сам выбирает сеть и держит только один VPN                                                      |

## Сборка

Нужны Node.js 24, JDK 21 и Android SDK (platform 36, build-tools 36).

```bash
npm ci
npm --prefix mobile ci
npm --prefix mobile run fetch:core
npm --prefix mobile run apk:debug
```

`fetch:core` скачивает `libv2ray.aar` (2dust/AndroidLibXrayLite) и `geoip.dat` / `geosite.dat` (из релиза XTLS/Xray-core) той же версии, что десктопный Xray, и сверяет SHA-256 с опубликованными. APK лежат в `mobile/android/app/build/outputs/apk/`: отдельно для `arm64-v8a`, `armeabi-v7a`, `x86_64` и универсальный.

Для релизной подписи задайте `ULTIMA_KEYSTORE_FILE`, `ULTIMA_KEYSTORE_PASSWORD`, `ULTIMA_KEY_ALIAS`, `ULTIMA_KEY_PASSWORD` (переменные окружения или свойства Gradle) и запустите `npm --prefix mobile run apk:release`. Без них релизный APK подписывается отладочным ключом.

## Проверки

```bash
npm run typecheck:mobile
npm run test:mobile
```

`test:mobile` гоняет бэкенд и интерфейс в jsdom с поддельным нативным плагином (`mobile/test/fakeCore.ts`): подключение, переподключение к другому серверу, отключение из уведомления, перехват VPN другим приложением, маршрутизация по приложениям, пинг без сессии и его блокировка во время сессии. `mobile/src/platform/conformance.ts` на этапе проверки типов следит, чтобы Android-замены покрывали всё, что десктопный код вызывает у оригинальных модулей.

## CI и релизы

- **Pull request** (`verify.yml`): задача `mobile` проверяет типы, гоняет тесты и собирает WebView-бандл; задача `android` собирает отладочные APK. APK для `arm64-v8a` и универсальный прикладываются к запуску как артефакт `UltimaVLESS-Android-debug` на 7 дней — их можно скачать со страницы проверок и поставить на телефон.
- **Релиз** (`release.yml`): задача `build-android` собирает APK, подписывает их ключом из секретов и выкладывает в релиз вместе с `SHA256SUMS-android.txt`. Без ключа релиз выходит без APK, а в запуске остаётся предупреждение.

Ключ подписи нужен один на всё время жизни приложения: Android ставит обновление поверх установленного APK, только если подписи совпадают. Потеряете ключ — пользователям придётся удалить приложение и поставить его заново. Создать ключ и добавить секреты:

```bash
keytool -genkeypair -v -keystore ultimavless-release.jks -alias ultimavless -keyalg RSA -keysize 4096 -validity 36500
```

```bash
base64 -w0 ultimavless-release.jks | gh secret set ANDROID_KEYSTORE_BASE64
```

```bash
gh secret set ANDROID_KEYSTORE_PASSWORD
```

```bash
gh secret set ANDROID_KEY_ALIAS --body ultimavless
```

```bash
gh secret set ANDROID_KEY_PASSWORD
```

Сам `.jks` храните вне репозитория, с резервной копией.

## Обновления

Приложение проверяет последний релиз на GitHub и ищет в нём `UltimaVLESS-Android-<версия>-<abi>.apk` (или `-universal.apk`). Новая версия скачивается в фоне, кнопка установки открывает системный установщик.
