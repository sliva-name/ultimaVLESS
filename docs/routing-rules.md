# Правила маршрутизации (split tunneling)

**Настройки → Сеть → «Правила маршрутизации»** определяют, какой трафик идёт через VPN, а какой — напрямую через обычное подключение. Правила сохраняются кнопкой **«Сохранить»** внизу вкладки и применяются при следующем подключении (во время подключения раздел заблокирован).

## Режимы

Режим задаёт маршрут **по умолчанию** — для трафика, который не подошёл ни под одно правило.

| Режим | По умолчанию | Какие списки действуют |
| --- | --- | --- |
| **Весь трафик через VPN** (как раньше) | VPN | Исключения, приложения напрямую |
| **Только выбранные сайты** | напрямую | Сайты через VPN, исключения, приложения напрямую |
| **Только выбранные приложения** | напрямую | Приложения через VPN, исключения, приложения напрямую |

Списки «Сайты через VPN» и «Приложения через VPN» сохраняются, даже когда выбран другой режим, — при возврате в режим они восстанавливаются.

## Списки

| Список | Куда | Что можно добавить |
| --- | --- | --- |
| **Сайты через VPN** | VPN | Домены, IP-адреса, CIDR, `geosite:` / `geoip:` |
| **Исключения из туннеля** | напрямую | То же самое |
| **Приложения через VPN** | VPN | Имена исполняемых файлов (`chrome.exe`) |
| **Приложения напрямую** | напрямую | Имена исполняемых файлов |

### Как записываются сайты

| Запись | Что совпадает |
| --- | --- |
| `example.com` (или `*.example.com`, `https://example.com/путь`) | `example.com` и все поддомены: `www.example.com`, `a.b.example.com` |
| `full:example.com` | Только `example.com`, без поддоменов |
| `keyword:example` | Любой домен, содержащий `example` |
| `geosite:youtube` | Готовый список доменов из `geosite.dat` |
| `1.2.3.4`, `10.0.0.0/8`, `2606:4700::/32` | IPv4/IPv6-адрес или подсеть |
| `geoip:telegram` | Готовый список адресов из `geoip.dat` |

`regexp:` не поддерживается: ошибочное выражение замедляет маршрутизацию всех соединений.

### Как работают приложения

Приложение определяется по **имени исполняемого файла** процесса, которому принадлежит соединение (Xray-правило `process`; на Windows — через таблицу соединений ОС `GetExtendedTcpTable` / `GetExtendedUdpTable`). Хранится только имя файла, без папки, поэтому правило продолжает работать после обновления программы, которая переезжает в новую папку (Discord, Telegram).

- **Имя сравнивается с учётом регистра**: `Discord.exe` и `discord.exe` — разные имена. Поэтому надёжнее выбрать программу из списка или нажать **«Выбрать файл…»**. Поле ввода открывает список запущенных программ с иконками и описаниями: поиск идёт по имени файла и описанию, список прокручивается, работают стрелки, Enter и Esc. Имя берётся из пути к файлу — так же, как его видит Xray. Введённое вручную имя приводится к написанию запущенной программы. Программы Windows (`explorer.exe`, `svchost.exe`) собраны в конце списка.
- У некоторых программ сеть работает во вспомогательных процессах (`steamwebhelper.exe`, `msedgewebview2.exe` и т. п.) — добавьте каждый.
- В режиме **TUN** правила для приложений охватывают все программы. В режиме **Прокси** — только те, что сами используют системный прокси; остальные программы и так идут напрямую.

## Приоритет правил

Xray проверяет правила сверху вниз и применяет первое подходящее:

1. Служебные правила: статистика, DNS (запросы на порт 53 и запросы встроенного DNS-модуля).
2. Проверки соединения UltimaVLESS — всегда через VPN (только в режимах «Только выбранные …»).
3. Блокировка рекламы и BitTorrent (если включена).
4. **Приложения напрямую.**
5. **Сайты и адреса**: исключения и сайты через VPN. Более точное правило важнее общего: `music.yandex.ru` важнее `yandex.ru`, `full:example.com` важнее `example.com`, `geosite:` и `keyword:` — самые общие. При равной точности побеждает исключение. Доменные правила проверяются раньше правил по IP.
6. Локальная сеть (`geoip:private`) — напрямую.
7. **Приложения через VPN.**
8. Маршрут по умолчанию — по режиму.

Что из этого следует:

- Приложение из списка «напрямую» идёт напрямую всегда, даже если оно же есть в списке «через VPN» или открывает сайт из списка «через VPN».
- Исключения сильнее приложений через VPN: например, `vk.com` из исключений откроется напрямую и в браузере, который отправлен через VPN.
- Локальная сеть (роутер, принтер, NAS) доступна и приложениям, отправленным через VPN.
- Явно добавленные в «Сайты через VPN» частные адреса (например, `10.0.0.0/8` для корпоративной сети за VPN) идут через VPN — правило сайтов стоит раньше правила локальной сети.

## DNS, IPv4/IPv6 и соединения без домена

- Доменные правила срабатывают по имени сайта из TLS (SNI), HTTP (Host) или QUIC — его определяет sniffing. Поэтому сайты, у которых много IP-адресов (CDN), обрабатываются корректно: важен домен, а не адрес.
- Если имя определить нельзя (не TLS/HTTP, нестандартный протокол), работают только правила по IP — добавьте адрес, подсеть или `geoip:`-список.
- DNS-запросы во всех режимах уходят через туннель на выбранный удалённый DNS (Cloudflare, Google, Quad9 или свой). Запросы делает системная служба DNS, а не само приложение, поэтому DNS не делится по приложениям. Для сайтов, идущих напрямую, адрес тоже определяется через туннель — это защищает от утечки DNS, но CDN может выбрать узел ближе к VPN-серверу, чем к вам.
- IPv4 и IPv6 обрабатываются одинаково: в списках можно указывать IPv6-адреса и подсети, `geoip:private` включает локальные IPv6-диапазоны. Получит ли браузер IPv6-адрес в TUN, зависит от настройки «DNS в TUN».

## Петли и совместимость

- Собственные соединения Xray к VPN-серверу не проходят через правила маршрутизации и в TUN-режиме привязаны к физическому адаптеру, поэтому трафик туннеля не может попасть обратно в туннель — даже если добавить `xray.exe` в «Приложения через VPN». Имена с `/` (специальные значения `self/`, `xray/`, пути и папки) в списки не принимаются.
- В TUN-режиме приложения «напрямую» по-прежнему проходят через адаптер UltimaVLESS и Xray, но выходят в сеть через обычный адаптер с вашим реальным IP.
- При переключении сервера новый экземпляр Xray получает те же правила, поэтому приложения и сайты «напрямую» не попадают в VPN и во время переключения.
- В режимах «Только выбранные …» правила подписки (JSON-конфиги), отправляющие трафик в VPN, отбрасываются — через VPN идёт только выбранное вами. Блокирующие правила подписки сохраняются.
- Проверки соединения UltimaVLESS (`connectivitycheck.gstatic.com`, `captive.apple.com`, `www.msftncsi.com`, `1.1.1.1` по HTTP на порту 80) в режимах «Только выбранные …» всегда идут через VPN: иначе они проходили бы напрямую и не замечали бы неработающий сервер.
- Настройки старых версий открываются в режиме «Весь трафик через VPN» с прежними исключениями; итоговая конфигурация Xray для них не меняется.

## Примеры

### Весь трафик через VPN, кроме игр и банков

1. Режим **«Весь трафик через VPN»**.
2. **Исключения**: `sberbank.ru`, `gosuslugi.ru`, `vk.com`.
3. **Приложения напрямую**: «Выбрать файл…» → `steam.exe`, `steamwebhelper.exe`.

Steam и указанные сайты идут через обычное подключение, всё остальное — через VPN.

### Через VPN только YouTube и Discord

1. Режим **«Только выбранные сайты»**.
2. **Сайты через VPN**: `youtube.com`, `googlevideo.com`, `ytimg.com`, `discord.com`, `discord.gg`, `discordapp.com`, `discordapp.net`, `discord.media` (или `geosite:youtube`, `geosite:discord`).
3. Для голосовых каналов Discord, которые идут по IP без домена, добавьте их адреса или подсети.

Указанные сайты открываются через VPN, остальные — напрямую.

### Через VPN только Telegram и браузер

1. Режим TUN (чтобы правила видели все программы).
2. Режим маршрутизации **«Только выбранные приложения»**.
3. **Приложения через VPN**: `Telegram.exe`, `chrome.exe` (из списка запущенных программ или через «Выбрать файл…»).
4. По желанию **исключения**: `vk.com` — откроется напрямую даже в Chrome.

Остальные программы подключаются напрямую.

## Как проверить

1. **Настройки → Сеть → «Уровень логирования»** — `debug`, сохраните и переподключитесь.
2. Откройте сайт или запустите программу.
3. **Настройки → Диагностика → «Скопировать логи»**: в журнале Xray для каждого соединения есть строка `taking detour [proxy]` (через VPN) или `taking detour [direct]` (напрямую).
4. Верните уровень логов `warning`: в режиме `debug` журнал записывает адреса всех посещённых сайтов.
